# 漏洞不收清单（判定权威）

> 只管一件事：什么不算漏洞、不写报告。**只在用户明确否掉某一类之后才记**；不许自己往里加，也不许自己放宽。
> 与 `打穿短表.md` 及各 `*-test.md` 冲突时，以本清单 + `AGENTS.md` 红线为准——短表里对应的「出什么算成」同步失效。
> 每加一条必须带：**覆盖范围 / 仍然算的边界 / 来源 / 日期**。拿不准就不记，先问。

## 一、硬不收（用户已确认）

### 1. 账户名枚举 → 不算

- **来源**：用户 2026-09-17 确认
- **覆盖**：注册 / 登录 / 找回密码 / 短信发送 等接口，靠回包差异、状态码、响应长度或时序区分「账号是否存在」。含「格式通过即 success」这类可枚举回包。
- **仍然算的边界**：
  - 枚举只是前置步骤。若据此真拿到**账号接管、撞库成功、批量有效凭证**，报接管 / 认证缺陷那一条，**不报枚举**。
  - 枚举出的标识本身敏感（身份证 / 工号 / 内部邮箱 / 真实手机号被回显）→ 按**信息泄露**报，不按枚举报。
- **不写**：单独的「可枚举」小节；不把枚举列进危害行。

### 2. 未授权读取非敏感消息 → 不算

- **来源**：用户 2026-09-17 确认
- **判定线一句话**：读到的是**别人的、非公开的、有归属的数据**才算；「没登录看到一条本来就给所有人看的内容」不算。
- **算（敏感）**：PII（手机 / 身份证 / 住址 / 学历 / 姓名）、凭据与密钥 token、他人业务数据（订单 / 名单 / 工单 / 合同 / 金额 / 证照）、内部经营数据（未公开商促 / 财务 / 客户名单 / 过程稿）。
- **不算（非敏感）**：面向所有人公开的公告 / 通报 / 文案 / 产品介绍、已公开的运营内容、自己的数据。
- **已作废产出**：`报告/_作废/联想大联想伙伴网未授权读取内部商促通报.md` —— 用户 2026-09-17 判定属本类，**整篇作废**。该站点「未登录可列通报库 + 直下附件」的通道**不作为漏洞**，需要时只当资产面记录。

### 3. 密钥 / 凭据泄露 → 须证实可用才算

- **来源**：用户 2026-09-17 确认（与 `info-leak-test.md` 首段「须假值对照，认钥枪带出身份或列表，再打不影响线上的只读例才交」一致，本清单把它升为硬规则）
- **覆盖**：RSA / 私钥（含从公钥还原）、API secret、云 AK/SK、token、账密、签名密钥、JWT 密钥。
- **算「证实可用」**——必须对**真实数据或真实接口**产生可观测效果：
  - 私钥 / 对称密钥：解开**真实抓包或真实业务密文**，或加密后**服务端接受**
  - API secret / 云 AK / OAuth 凭证：**换到有效 token**，或调通只读接口**带出身份 / 列表 / 对象**
  - 账密 / token：**登得进去**，并读到带归属的数据
- **不算**：只「泄露了」；只「可还原 / 可推断」；只通过格式、长度或指纹校验；**本地加解密 round-trip 自检通过**；本地分解成功但没碰过任何真实数据。
- **对照纪律**：同结构的**假值**打一发，必须失败。没有对照不发。
- **不落口令**：验证过程解出的明文口令 / 验证码 / token **一律不写进报告、不落盘、不进对话**；只写字段名与长度。
