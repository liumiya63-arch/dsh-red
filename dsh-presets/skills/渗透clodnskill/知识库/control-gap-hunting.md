# 控制缺口（Control Gap）狩猎

> 学自 [dsh-redteam-model](https://github.com/SeaOf0/dsh-redteam-model) `modes/pentest/refs/zh/methodology/04-control-gap-hunting.md`。插件不装，只吸收打法。
>
> 白盒问「代码里有没有这个控制」；黑盒问「这个控制现在真的生效吗」。本仓库默认授权 SRC，进站仍认 `dig-scope`。写不写只认 `vuln-report-format.md`。

## 一、一句话

看见一个**敏感操作**，先写出它**应有的控制**，再逐条证伪。控制缺了或只挡了前端 / 只挡了一条 path，就是洞。

不要上来对每个 path 喷 `'`。先画操作 → 控制，再选模块。

## 二、敏感操作 ↔ 应有控制

| 敏感操作 | 应有控制（至少一项真生效） | 黑盒怎么探 | 过了开哪篇 |
|---|---|---|---|
| 读别人的订单 / 房 / 表 / 档案 | 会话主体 = 资源主体；或 ACL | 同一张票换邻 id；无票对照 | `idor-test.md` |
| 改绑 / 改密 / 改角色 | 旧验（旧密/短信/二次确认）+ 只能改自己 | 拿掉旧验；换别人 id | `authbypass-test.md` |
| 管理接口 | 角色 / 权限码，不只是「登录了」 | 普通票打 `/admin` `/manage` `/pms` | `idor-test.md` BFLA |
| 租户列表 / 附件 | `tenantId` 以服务端会话为准，不跟 query | 哨兵 `0`/`-1`/空；附件 URL 只改租户 | `idor-test.md` 哨兵租户 |
| 解微信手机号密文 | 服务端 `session_key`，客户端不持有 AppSecret | 解包 + 流量里找 secret；没有则不是密钥洞 | `miniprogram-test.md` |
| 支付 / 计价 | 金额服务端算；券归属 + 商品归属 | 改金额/改别人 productId | `logic-test.md` |
| 上传后访问 | 鉴权 + 类型 + 路径不在 web 根 | 换 Content-Type / 跨用户 key | `file-upload-test.md` |
| 服务端取 URL | 协议/IP 白名单，元数据拦截 | 回环对照再打 IMDS | `ssrf-test.md` |
| 网关鉴权 | 规范化后仍鉴权；gRPC/SSE 同一套 | `../` `;` 编码；反射列方法 | `api-gateway-test.md` / `grpc-sse-test.md` |
| 高危写（开断电、删库、转账） | 二次确认 + 对象归属 + 审计 | 只读证伪；写要最小伤害 | 用户授权后再打 |

「前端隐藏按钮」「query 带了 openid」「网关名字叫 gateway」都不是控制。控制必须在**执行敏感操作的那一层**挡住。

## 三、黑盒探测顺序

1. **点名操作。** 这句话能说清：谁、对什么对象、做什么。说不清就先跟流量 / 解包，别开扫。
2. **列控制。** 身份（有没有票）、对象（是不是自己的）、租户、角色、旧验、频率。写在清单上。
3. **拆控制。** 一次拿掉一个：去票、换 id、换租户、拿掉旧验、改 METHOD、改网关前缀。
4. **对照。** 完整合法请求 vs 拆掉控制的请求。差分在业务数据，不在「都是 200」。
5. **定位缺口在哪一层。** 前端没按钮但 API 通 = 前端控制。网关 401、直连后端 200 = 网关缺口。票绑用户、id 仍自由 = 对象级缺口。

一次只证一条缺口。不要把三个差分写成一个洞。

## 四、证据纪律（从他们 methodology/03 收的）

报洞必须是原生证据，不是「我猜的」：

- 请求 + 回包（或 Yakit tab / 分组名）。敏感值打码。
- 对照：自己的对象 vs 邻对象，或有票 vs 无票。
- 复现路径短：别人按步骤能再打出同一差分。
- 不要用扫描器摘要代替回包。nuclei 命中只是线索。
- 控制「看起来有」但没生效：把失效的那一层写进报告（前端 / 网关 / 对象 id）。

## 五、SRC 时间盒（从他们 methodology/05 收的）

同一面上，力气按这个顺序砸，不要平均：

1. 未登录敏感读 / 对象级水平越权 / 认证链发票
2. 垂直越权、租户、逻辑计价
3. 有差分面的注入 / SSRF / 上传
4. 指纹、版本、缺头、点击劫持

小程序 / 前后端分离：先对象图，再四件套。登录页不是换资产的理由。

## 六、和本仓库其它篇的关系

- 短表：形态对得上就开对应篇，本篇不替代短表。
- 短表没有的操作：用本篇列控制再打。
- 白盒：用户给了源码，按调用链找「敏感 sink 前面缺守卫」，不要全仓 grep 关键字当审计。
